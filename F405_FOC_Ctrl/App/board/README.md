# ADC/PWM 后端接入说明

上电先监测母线，在9～27 V连续稳定1秒后分别检查 M0、M1 的驱动器和电流校准，`MotorHw_Init()` 返回可用轴位掩码：
0=无可用轴，1=仅 M0，2=仅 M1，3=两轴。单轴失败仅关闭对应 EN_GATE。
ADC 保留双 Rank 时序，TIM1 保留共享触发职责；仅 M1 可用时仍须运行 TIM1 计数器。
显式使能时应用再检查每轴编码器、母线、电流和反馈完整性，只启动有效轴，不等待两轴同时有效。
无可用轴时，应用在电压重新稳定1秒后重试初始化，已有可用轴时不重复初始化。初始化成功不自动开启输出；运行中的电压/软件过流恢复另由应用处理。这里的有效性不等于检测电机三相线已连接。

调试器可读取 `g_adc_current_init_result` 查看共享 ADC 后端，
读取 `g_adc_current_axis_result[0/1]` 查看 M0/M1 独立校准结果：
0=尚未启动/未通过校准进入正常采样，1=成功，2=时钟配置失败，3=驱动器进入校准失败，
4=ADC2 启动失败，5=ADC1 启动失败，6=ADC1 转换超时，7=ADC2 转换超时，
8=该轴零偏超出 1536～2560，9=退出校准失败，10=正常触发采样启动失败。
3、8、9 由各轴结果报告，2、4～7、10 由共享结果报告；驱动器检查失败的轴不进入校准。
退出校准的清理操作保留最初的失败原因；这些诊断不会绕过启动检查。

编译验证直接使用 `MDK-ARM/F405_FOC_Ctrl.uvprojx` Keil 工程。
编译通过不替代实板模拟电路及 PWM 时序测量。

对外仍使用 `motor_hw.h` 的四类接口。`adc_current` 为内部采样后端，
`drv8303` 负责增益配置、启动检查与内部短接切换，不改写驱动器保护参数。

## 原理图映射

依据 `../Schematic/双路BLDC的有感FOC驱动器.pdf`（相对工程根目录的上一级）。

| 项目 | M0 | M1 |
| --- | --- | --- |
| A 相电流 | PC0 / ADC1 注入 Rank 1 | PA1 / ADC1 注入 Rank 2 |
| B 相电流 | PC1 / ADC2 注入 Rank 1 | PA0 / ADC2 注入 Rank 2 |
| A/B/C 高侧输入 | TIM1 CH3N/CH2N/CH1N | TIM8 CH3N/CH2N/CH1N |
| A/B/C 低侧输入 | TIM1 CH3/CH2/CH1 | TIM8 CH3/CH2/CH1 |

- 分流电阻为 5 mΩ。DRV8303 的 SP 接电阻地端、SN 接低侧源极，电流流入电机为正。
- 初始化将两轴电流放大增益设为 20 倍，读回确认后使用该配置值计算电流换算系数。
- PA4 为 ADC1 规则组母线输入，200 kΩ/10 kΩ 分压，换算倍率 21。
- ADC 使用标称 A3V3 = 3.3 V 和 12 位的 4096 个量化区间；实板精度需测量参考电压。
- PWM2 的互补输出连接高侧，理想高侧占空比为 CCR/ARR，死区会影响实际导通时间。

## 初始化和读取

`MotorHw_Init()` 仅在 CubeMX 初始化之后从前台调用，不要求电机静止。
先关闭 MOE，确保主输出和互补输出的空闲电平全部为低，再拉高 EN_GATE 唤醒电流放大器。
等待 10 ms，通过 `Drv8303_SetCurrentGain()` 设置两轴增益为 20 倍并读回确认，
由 `Drv8303_CheckStartup()` 检查 6-PWM 模式、校准关闭和状态寄存器 1 无故障，
通过 SPI 设置两轴 DRV8303 控制寄存器 2 的 D4/D5，将放大器输入断开并内部短接。
等待 1 ms 后用 256 次软件触发的双 ADC 注入序列计算四路零偏，
随后清除 D4/D5，保留增益及其他配置，等待 1 ms 后启动正常采样。
内部短接使零偏测量不依赖分流电阻中的实际电流；不等同于带转闭环接管已完成。
校准和启动统一放在 `AdcCurrent_Init()`，不再提供独立 Start/Stop 接口。
校准失败时也尝试恢复候选轴正常输入，仅剔除校准失败轴；共享 ADC 故障返回 0。
硬件层关闭未通过检查或校准的轴；至少有一路成功即可继续初始化。

成功后两路 PWM 计数器同步运行，MOE 仍为零，不输出驱动脉冲。
TIM1 OC4REF 触发 ADC1/ADC2 注入电流转换。
`adc_monitor` 从前台每 10 ms 用 ADC1 规则组发起一次 PA4 母线电压采样，
使用现有 DMA2_Stream0、半字、DMA_NORMAL 配置，将一个 ADC 值传入常规 SRAM，
由 DMA 完成回调换算电压并发布缓存。前台不轮询 EOC、不等待转换。
DMA 忙时不提交下一次采样，完成后保持 ADC 开启，注入组电流采样继续运行。
ADC3 两路 NTC 仅保留 `AdcMonitor_ReadNtcRaw()` 接口，尚未启动采样。

TIM5 专用作 1 MHz、32 位时间基准，不可被其他功能重复初始化。
电流中断按 TIM1 中心对齐计数相位回推 OC4REF 触发时间，
按当前 ADC 21 MHz、15 周期采样、12 周期转换，估计 M0/M1 保持时刻为触发后 1/2 us。
`current_time_us` 使用各轴自己的估计时刻，编码器角度用机械速度外推到此时刻并折回单圈。
这是一阶恒速估计，分辨率为 1 us；没有额外补偿编码器芯片内部延迟，仍须实板验证误差。

`ReadSample()` 返回 true 表示取得电流快照，交给 FOC 前必须同时满足
`sample.feedback_complete && sample.faults == 0`。
首帧速度未建立或母线数据尚未取得时 `feedback_complete` 为 false；
编码器缺帧、告警、通信错误或请求时间超过 2 ms 时设置 `MOTOR_FAULT_ENCODER`。
`EncMt6826s_ReadLatest()` 在下一帧 DMA 进行中提供上一帧结果，但总线故障后不返回旧的正常结果。
重复读取或电流帧超过 150 μs 由电流采样层设置 STALE；母线超过 30 ms 未更新，
由监测层返回 false，再由 `motor_hw` 映射为 `MOTOR_FAULT_BUS_SAMPLE`。
这两项时限是目前的采样诊断配置，不等价于独立的超时关断。

固定的定时器模式在初始化检查一次。`WriteDuty()` 验证参数，
使用 `__HAL_TIM_SET_COMPARE` 写三路 CCR 预装载，不改变 CH4 触发点，
不产生 UG，不打开 MOE。写入期间短暂禁止更新事件，使三相在同一后续更新事件生效。

## 功率输出

`App_Poll()` 默认每 200 μs（5 kHz）提交一次有效轴的编码器读取，维持反馈更新；周期由 `APP_ENCODER_PERIOD_US` 设置。
请求间隔使用 TIM5 微秒时基；SPI 忙时不推进请求时间，下一轮前台继续提交，避免漏一周期造成反馈过期。
硬件初始化失败时不提交读取；通信故障后仍由上层决定何时重新初始化。

`App_Init()` 加载配置并启动母线采样，保持两轴输出关闭；`App_Poll()` 在电压稳定后完成驱动和电流采样初始化。显式使能时最多等待10ms，确认反馈、母线、电流及PWM预装载更新后独立开启该轴。
超时或初始化失败的轴不打开输出，主循环仍继续监测和 USB 服务。
`control_running` 为运行轴位掩码，0/1/2/3 分别表示无轴/M0/M1/双轴。运行关断后仅电压/软件过流按应用恢复规则处理。
临时的固定电压开环输出及其接口已删除；VOFA 选择不再限制控制调度。
默认算法初始目标为 Id=Iq=0；当前电机极对数为 7，方向和电角零位由 `Command_CalibrateMotor()` 标定。

电流 ADC 完整帧发布后，通过 `AdcCurrent_OnSample()` 通知应用，在 ADC IRQ 内依次对运行轴执行
`ReadSample → MotorControl_Step → WriteDuty`，当前为 20 kHz 电流环、速度模式下五分频 4 kHz 速度环。
运行时使用同一有效性条件检查反馈和 8～28 V 电压范围，失败或 PWM 写入失败时只关闭对应轴并复位其算法，
不会在下一拍自动恢复。共享 ADC、母线或 SPI/DMA 故障会使两轴反馈失效，分别关断两轴。
每轴快照也报告对应定时器 Break 标志。仅上电驱动自检通过时清除唤醒前的旧标志，运行中不清故障。
母线仍为每 10 ms 更新一次。

启动顺序：

1. 上层配置电机极对数、编码器方向、电角零位，并确认运行许可。
2. 读取完整、无故障的反馈，计算并写入启动占空比。
3. 跨过一次 PWM 更新事件，再取得新一拍完整反馈，调用 `MotorHw_SetOutputEnabled(axis, true)`。

开启只检查初始化、占空比已写入且发生过预装载更新、计数器运行。
反馈完整性、时效和运行许可统一由上层决定；读取快照不再修改输出开启许可。
设置 MOE 后读回，若硬件 Break 仍阻止输出则返回 false；不清除 Break 故障。
关闭仅清 MOE，保持 EN_GATE 高及电流放大器工作，反馈继续运行；重新开启须重新装载占空比，并由上层确认反馈有效。
开启失败不会自动关闭已经运行的输出；上层按返回值与快照 faults 决定停机。
同一轴的读取、PWM 写入和启停操作由上层串行调用。

当前固定采样配置为 TIM1 CCR4=3864、M0 死区 80 tick、M1 死区 96 tick、放大增益 20、ADC 注入采样 28 cycles。
按用户要求取消固定 35%～65% 测试范围及对应的 1120 tick 占空比拒写判断。
`MOTOR_HW_DUTY_MARGIN=0.05`，`MotorControl_DefaultConfig()` 使用此值，恢复 FOC 的 5%～95% 调制范围。
ADC 触发位置和采样时间未随占空比动态调整；20 倍增益、100 Ω/10 nF 在高占空比下不保证低侧电流采样已稳定或处于有效导通窗口。
占空比写入成功和 `feedback_complete` 仅代表写入成功及反馈数据完整，不证明高占空比下电流测量准确；扩大调制范围尚未经过实板验证。

应用检查8 V欠压、28 V过压和实测三相电流，软件过流阈值为 `1.25 * current_limit_a + 0.2 A`。
电压连续恢复至9～27 V满1秒后自动使能；软件过流等待至少2秒且三相电流均小于0.2 A，只重试一次，第二次过流等待手动使能。
恢复后旧目标及积分归零，正常停机取消恢复；硬件Break、反馈及PWM错误不自动恢复。详细规则见[配置说明](../config/README.md#运行关断与恢复)。
前台使用诊断快照检查过期反馈，即使 ADC 回调停止也会关断输出；该检查依赖主循环持续运行，不是独立硬件看门狗。
实际采样孔径、编码器延迟、死区和相序仍应示波器验证，原理图不能代替实测。

## 验证方式

### 编码器方向与电角零位标定

`App/comm/command.c` 提供命令入口和参数校验；`App/motor_calibration.c` 执行标定流程与保护。
命令层先正常停止两轴并保存未校准状态；标定模块执行方向/零位测量，返回时输出保持关闭。
成功后命令层把结果和 calibrated=1 写入 EEPROM，读回核对后保持输出关闭，等待显式 enable 命令。
`app.c` 根据现有标定状态暂停该轴正常调度、保持编码器读取，并从 ADC 回调和前台调用保护监测；无专用 Begin/End 接口。
后续 USB/CAN 只记录请求，在前台调用命令接口，不能在接收中断里执行标定。

需要完整校准时在 `App_Init()` 返回后，从前台调用一次 `Command_CalibrateFull()`，或 USB 配置/HOST模式发送 `calibrate 0`；不要放在每轮 `App_Poll()` 中，
也不要从中断调用。它是同步接口，内部持续运行 `App_Poll()`，ADC/SPI/USB 中断照常运行。
同一时刻只标定一轴；因 EEPROM 操作会阻塞前台，调用前两轴均须关闭，否则返回 BUSY。电机须空载、可自由转动。

```c
#include "command.h"

/* 两轴关闭后前台按需调用；依次找零、齿槽标定并保存，输出仍关闭。 */
char reply[128];
Command_CalibrateFull(MOTOR_AXIS_M0, reply, sizeof(reply));
/* reply 为 OK CALIBRATED_FULL 才表示两阶段完整成功。 */
```

不再传参数结构体。完整入口复用找零和齿槽模块，状态帧报告ZERO/COGGING阶段，失败回复指出阶段。
找零失败不进入齿槽；完整流程的零位中间结果只留RAM，齿槽失败或掉电保持未完成校准。成功后统一保存表与零位。存储失败另报EEPROM错误，需读取确认。
`Command_CalibrateMotor()` 保留仅找零的调试入口；以下说明为找零阶段，其沿用现有极对数、限幅和PI设置。
`motor_calibration.c` 集中设置标定幅值 `CAL_VOLTAGE_V=0.4 V`、实测相电流关断上限 `CAL_CURRENT_LIMIT_A=3 A`、
定位时间 `CAL_SETTLE_MS=500 ms`、单向扫描时间 `CAL_SWEEP_MS=1500 ms`、辨向角 `CAL_PROBE_ANGLE_RAD=pi` 电角度。
实际关断阈值取该轴 `current_limit_a` 和 3 A 中较小值；它监测实测相电流，不是标定电流闭环，也不同于正常运行的 10 A Iq 指令上限。
这些设置不是所有电机通用值；电压过低会定位失败，不自动加压重试。更换电机时应确认其允许电流与已有极对数。

流程：缓慢升压至正 alpha 轴并定位 → 正向扫描半个电周期 → 反向返回并定位 → 测量零位，正常约5.2 s。
两次扫描计入扫描后定位期间的位移，必须方向相反，机械位移幅度与 `pi/pole_pairs` 的误差不超过20%；少于预期10%判为没有跟随。7极对电机单向预期约25.7°。
只在最终定位处采集 200 ms 的独立编码器帧做圆周平均，不再比较三次定位的一致性或增加角度集中度门限。
方向由正向扫描时编码器角度增减确定，零位按 `direction * pole_pairs * mechanical_angle` 做圆周平均。
本流程不使用尚未标定的角度执行电流 PI，不修改电流采样、速度低通或速度环频率。

返回值：0=成功，1=参数/调用上下文无效，2=已有轴正在标定，3=本轴未就绪，
4=反馈异常或应用故障已锁存，5=母线越界，6=实测相电流超限，7=PWM 操作失败，8=未跟随，9=正反扫描位移不匹配，10=EEPROM 保存/核对失败。
成功时直接更新该轴 `encoder_direction` 和 `electrical_zero_rad`；
标定失败不更新参数，保持本轴关闭并锁存故障；参数无效/忙时不改变现有运行。
成功后保持两轴关闭。发送 enable <axis> 1 检查实际使能成功后，再下发速度目标。
使能时须反馈完整、无采样故障、母线正常且预装载更新完成；显式使能成功后解除本轴软件锁存，不清硬件Break。失败返回 ERR ENABLE 和原因，不自动重试。
测得的方向和零位保存在 EEPROM；运行故障与校准结果分别处理。
有未保存修改时返回 3，须先 `param save`。保存失败保持两轴停止，不自动重试，不写 MCU Flash。
需要查看结果时可接收返回值；通过 `MotorControl_GetConfig(axis)` 查看该轴零位和方向。
本接口不验证电流环 PI 调参或电流反馈极性，标定成功后仍需先做小电流闭环验证。

状态指示灯由 `App_Poll()` 更新：LED2（PC15）绿色，LED1（PC14）红色，低电平点亮。
标定期间绿灯每 250 ms 切换一次亮灭；直接复用系统时基，不增加定时器或阻塞延时。红灯故障优先，发生母线异常时不闪绿灯。
母线低于 8 V、高于 28 V，或 M0、M1 均已因运行异常关断时，红亮绿灭；其余母线有效状态绿亮红灭。
异常关断位由 `App_StopAxis()` 或标定监测锁存，重新初始化清零；反馈恢复后也可显式使能本轴解除软件锁存。未装配、启动检测未通过而跳过的轴不计入。
母线数据尚未取得或已失效、且未发生两轴异常关断时，两灯均灭；绿灯不代表两路电机均正常。

使用 `MDK-ARM/F405_FOC_Ctrl.uvprojx` 在 Keil 中编译，随后实板检查采样和波形。
编译通过不能验证模拟电路、PWM 波形或真实定时器触发时序。

## 编码器速度

`EncMt6826s_Read()` 同时返回单圈绝对角度、`speed_rad_s` 和 `speed_valid`。
速度沿编码器原始正方向，使用两次正常帧的最短角差除以请求时间差，再调用 `EncMt6826s_FilterSpeed()` 做一阶低通。
截止频率由 `enc_mt6826s.c` 中 `ENC_SPEED_FILTER_HZ` 设置，默认 20 Hz，按实际请求时间差计算系数。
滤波不降低编码器更新或速度环调度频率，但会增加速度反馈延迟；角度保持原始值。
首帧、告警或数据间断时复位滤波值，再重新建立速度基准。
例如从 32760 到 8，角度计数差为 +16；反向跨圈则为 -16。
首帧、CRC/通信错误或告警后的首帧不计算速度；时间间隔为零或达到 2 ms 时也不计算。
使用速度前必须检查 `speed_valid`，并保证相邻请求之间机械转动小于半圈（默认 200 μs 请求周期）。
时间来自 `AdcCurrent_Init()` 启动的 TIM5；未启动该时基时只能取得角度。

编码器 CRC 错误仅标记对应轴，不覆盖上一正确角度、不取消另一轴请求；应用运行检查会锁存该轴停机。
SPI/DMA 或超时错误会取消本批请求并停止共享 SPI/DMA，不自动恢复。
上层从 `Read()` 取得错误后，自行决定何时从前台调用 `EncMt6826s_Init()`。
DMA 未完全退出时 Init 返回 BUSY，不会复用接收缓冲区；Init 成功后才接受新请求，
并从新的正常角度帧重新建立速度基准。`Service()` 推进未完成的另一轴请求和检查超时。

临界区工具为 `board_critical.h` 的 `static inline` 函数，无独立源文件。
`AdcMonitor_Init()` 在 `App_Init()` 中于电流采样初始化流程之后调用，
`AdcMonitor_Service()` 由 `App_Poll()` 持续调用。
`AdcMonitor_ReadBusVoltage()` 返回缓存电压（V），供上层按实际母线配置判断欠压和过压。
首次结果尚未取得或采样过期时返回 false，保持调用者输出不变。
NTC 接口当前同样返回 false，不填入虚假的测量值。

## EEPROM

`eeprom.c/.h` 为本板 24LC64-I/SN 的读写驱动，已加入 Keil 的 `Application/Board` 分组。
沿用 CubeMX 的 I2C1（PB6=SCL、PB7=SDA，100 kHz，开漏，芯片外部上拉），不重复初始化外设。
用户确认 A0/A1/A2/WP 均接 GND：7 位地址 0x50，传给 HAL 时为 0xA0；WP 低电平允许写入。
容量为 8192 字节（64 Kbit，不是 64 KB），页大小 32 字节，存储地址使用 16 位传输。

接口为 `Eeprom_Read(address, data, size)` 和 `Eeprom_Write(address, data, size)`，成功返回 true。
连续读取不受页边界限制；写入按实际页边界拆分，每页 ACK 轮询等待芯片完成写入（数据手册最大 5 ms）。
非法范围或通信失败返回 false；失败前可能已有部分数据读出/写入，返回 true 不包含数据读回校验。
地址按字节计，拒绝跨出 0x0000～0x1FFF；长度为零不访问总线，不提供擦除或自动故障重试。
仅在前台初始化或两路电机停止时调用，保持中断和系统时基正常；I2C1 必须独占。
接口为阻塞方式，整片读写耗时较长，不在运行中的 `App_Poll()` 或电流中断直接调用。
启动只读 EEPROM；`config_store` 负责参数格式和保存，底层驱动不处理电机配置。

参考开源驱动：[patsaoglou/st-m24c64](https://github.com/patsaoglou/st-m24c64)（MIT，许可保留在 eeprom.c）。
移植时改为字节地址接口、连续读，修正整页边界拆分并返回 HAL 操作结果，固定延时改为 ACK 轮询。
时序依据：[Microchip 24LC64 数据手册](https://ww1.microchip.com/downloads/en/devicedoc/21189r.pdf)。
固定格式及 USB 指令见 [配置说明](../config/README.md)。每轴 4 KB，其中 256 B 电机/校准参数、2048 B 补偿表、32 B 调试参数、1760 B 保留。

## USB 波形

当前 `main.c` 仅调用 `App_Init()` 和 `App_Poll()`，不自动校准或设置 100 rpm。
上电恢复 EEPROM 参数，两轴始终保持输出关闭；已保存且校准的轴收到 enable 命令才开启控制，USB 可随时配置。
速度 PI 和电流限幅由每轴配置提供；初值沿用 `MotorControl_DefaultConfig()`。`current_limit_a` 可设为 (0,10] A，仅限制速度环 Iq 指令及 USB 电流命令，不代表实测相电流过流关断。
当前 `MOTOR_CURRENT_GAIN=20`、ADC 28 cycles；驱动增益和电流换算共用该值，初始化按该增益校准零偏并解除输入短接。
放大器保持正常外部输入，通道 0/1 观察 Ia/Ib；硬件 C20/C22 为 10 nF，100 Ω 电阻保持不变。
已按用户要求恢复 5%～95% 输出范围；电流 PI、触发位置和 ADC 采样时间不变，零电流测试不代表扩大范围后的全速全负载验证。
按需执行零位校准会驱动电机定位和正反扫描；校准失败不启动正常控制。USB 上传运行波形，支持 speed、id、iq 命令。

`App_Poll()` 调用 `UsbVofa_Poll()`，以 VOFA+ JustFloat 上传十六个小端 float，
顺序固定为 A 相电流(A)、B 相电流(A)、C 相电流(A)、机械转速(rpm)、母线电压(V)、实际 Id(A)、实际 Iq(A)、
指令 Vd(V)、指令 Vq(V)、电压限幅状态(0/1)、机械角度(deg)、Iq目标(A)，上述前十二个通道顺序不变；
通道12/13追加M0/M1实际使能，14为最近enable命令的轴号，15为结果（1成功/-1失败/0无命令）。
后接 `00 00 80 7F`，每帧68字节。原有通道0～11无需重新绑定。
C 相由 `Ic = -Ia - Ib` 重建，并非独立采样。
通道 5～11 读取最近一次 FOC 的同拍结果，以短临界区保证一致；复位后尚无结果时发送 NaN。
机械角度为电流采样时刻的外推值，未修正编码器方向；Iq 目标为该拍实际送入电流环的指令。
Vd/Vq 是电流环限幅后的指令电压，并非实测端电压；限幅状态为抽取时刻的 0/1，不统计两帧之间的限幅事件。
在 `App/comm/usb_hostif.c` 修改 `USB_VOFA_AXIS` 选择显示轴，不影响命令轴或双轴控制，
在 `App/comm/usb_hostif.c` 修改 `USB_VOFA_PERIOD_MS` 选择上传间隔，默认 1 ms，实际频率受主循环和 USB 影响。
转速保留编码器原始方向，未使用控制参数中的方向修正。

USB 未配置、忙或未到发送时间时不等待、不排队；发送缓冲区在传输完成前保持不变。
尚未取得或无效的通道发送 NaN；电机后端未就绪时仍可上传独立母线测量。
速度通道等待完整反馈建立，使用编码器提供的低通速度；电流通道仅抽取采样点，未额外滤波，不代表完整的 20 kHz 电流序列。
本模块独占 CDC 发送接口，仅从前台调用；选择对应 COM 口、JustFloat 引擎后绑定通道 0～11。

VOFA+ 下发使用 Str/ASCII 文本命令 `speed <rpm>`，每条以实际换行结束。
电流测试发送 `iq 0.2`、`iq 0.3`（同样以实际换行结束），选择 Id=0、Iq 为给定安培值的电流模式，绕过速度环。
静止 d 轴阶跃发送 `id 0.2`、`id 0.3`，选择 Iq=0、Id 为给定安培值的电流模式；两种电流命令均清零另一轴目标。
`id` / `iq` 目标必须有限且绝对值不超过该轴 `current_limit_a`，否则忽略；`id 0` / `iq 0` 为零电流目标，不表示关闭 PWM。
例如 `speed 300`、`speed -200`、`speed 0`，最后一条表示零速目标，不表示关闭功率输出。
无轴号的旧指令默认 M0；`speed 1 100`、`iq 1 0.2`、`id 1 0.2` 可显式指定 M1。
CDC 回调只拼行，支持分包和 CR/LF，每行最多 127 字符；只保留第一条待处理行，忙时不覆盖。
发送 `config on` 暂停波形，进入文本配置/应答模式；`config off` 应答后恢复波形。
指令在前台且 CDC 发送空闲时处理，逐条发送并等待应答，`param show` 等待 END 行；配置模式报告 BUSY/LINE_TOO_LONG。
波形模式执行 speed/id/iq/enable，不混入文本应答；参数和校准指令须进入配置或HOST模式。
`host on` 回复 `OK HOST 1`，改为双轴50 Hz文本遥测，仍逐条回复命令；`host off` 恢复波形。
速度必须是有限数值；具体运行速度上限及许可由上层管理，本接口不自动启停硬件。
初始化成功开启输出后，命令会在下一次速度环更新时生效；启动失败或运行关断后，命令不会重新开启输出。

诊断使用 `MotorHw_PeekSample()` / `AdcCurrent_Peek()`，不修改电流控制读取的消费序号，
不因重复查看而产生 STALE；原有 `ReadSample()` 仍对控制侧重复消费报告 STALE。
两种读取共用采样快照和换算逻辑，均保留错误及过期检查。

## 错误与有效性约定

| 接口 | 返回值含义 | 数据有效性 |
| --- | --- | --- |
| MotorHw_Init / AdcCurrent_Init | 可用轴位掩码，0 表示无可用轴 | 按轴隔离失败，共享故障返回 0 |
| PWM及驱动设置 | 本次操作是否成功 | 失败原因由调用方按操作处理 |
| AdcCurrent_Read / MotorHw_ReadSample | 是否取得快照；false 不改输出 | 成功后检查快照 faults；完整反馈另看 feedback_complete |
| AdcMonitor_ReadBusVoltage | 是否取得新鲜电压；false 不改输出 | 不在这里判断运行欠压、过压 |
| 编码器请求/读取 | 协议结果，PENDING/BUSY 不是故障 | OK 表示角度正常，speed_valid 独立表示速度估计已建立；WARNING 仅供诊断 |

采样层负责数据完整性与时效，每项只检查一次，`motor_hw` 汇总而不重复计算。
`MOTOR_FAULT_BUS_SAMPLE` 表示母线数据无效；实际欠压/过压由应用判断，当前直接停机，尚未对外发布应用故障字。
同样，算法的 Iq/电压限幅属于控制计算，运行过流阈值、停机、故障恢复属于上层策略。
本次没有增加运行保护状态机或自动重试。

## EEPROM 运行中写入

电机固有参数和校准记录仍使用停机后的阻塞读写。速度Kp、Ki及齿槽补偿强度使用 `Eeprom_WritePageStart/Poll`，仅写每轴偏移0x900的独立32字节页。
I2C1事件/错误中断完成收发，前台等待至少6ms写周期后异步读回核对；期间继续服务编码器和控制。BUSY总线直接报告失败，不进入HAL入口的阻塞轮询，不自动重试。
发送及读回缓冲区保持到传输结束；核对成功后上层才热更新运行值。记录布局见 `App/config/README.md`。

## 中断与共享数据

- 电流帧仅由 ADC IRQ（优先级 1）发布，回调不全局关中断。
  读取只允许前台或优先级数值 >= 1 的中断；禁止 Break IRQ 读取。
  每轴一个串行读取者，临界区仅复制帧和错误字，序号/超时判断使用复制后的快照。
- 母线 DMA IRQ（优先级 6）可能被控制 IRQ 抢占，因此发布电压、时间戳、有效标志时仍用短临界区。
  读取时也只复制这三个字段，时间判断和返回值处理在临界区外。
- 编码器请求、DMA/SPI 回调和前台 Service 共享总线状态，继续保留已有的短临界区。
- PWM 三相写入继续保留短临界区及 UDIS，保证更新一致性。
- 初始化只在控制暂停且母线 DMA 未运行时执行，电流采样初始化先于母线监测初始化。

这些约定依赖当前 CubeMX 中断优先级；调整优先级或新增更高优先级读取者时需同步检查。
